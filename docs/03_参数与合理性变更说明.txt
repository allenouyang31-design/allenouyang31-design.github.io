新版原型：参数与合理性变更说明
2026-10-10 | 第一关受击反馈已通过针对性运行验证

阅读前提
本连续版不再改变战斗参数，沿用已验收的第一关冲锋受击/倒地修订与第二关AI挥击表现。第三关改为同一局原速完整展示两轮毒潮、实际击杀及本局结算；新版主片已导出，约3分24秒（203.9秒）；第三关独立原片约1分24秒（83.8秒）。两份视频均通过全片解码检查。
以下参数、实现与验证来自已保存蓝图、运行快照及针对性检查。完整技术记录保留在制作资料中，公开说明只呈现与设计判断有关的结果。

一、为什么改第一关
冲锋是经过跟随、锁定和路线判断后的关键攻击。如果被撞后只少量掉血且身体没有清楚反应，玩家难以识别失误的分量。本次把冲锋与普通震击的后果分开：冲锋伤害更重，增加短暂倒地与击退；普通震击保留原代价。
满血仍为5。冲锋请求伤害由原共享伤害1改为2，相当于满血的40%；这不是“每次必定实际扣2”。剩余生命不足2时，实际损血只能达到剩余生命，且死亡不会被恢复流程拉起。
0.8秒失控是当前设计起点：希望足以读出受击结果，又尽快归还操作。此选择没有经过外部玩家平衡验证，不声称已达到最佳手感。

二、三份蓝图各自负责什么

1. /Game/Step04/BP_GuardianGameMode
职责：统一判定伤害来源、去重同次冲锋、应用实际伤害、记录结果与结束战斗。

ChargeHitDamage = 2 HP
旧值：原共享伤害1。新值：冲锋单独使用2。
理由：让经过明显预警的冲锋产生比普通震击更清楚的风险。以5满血计，理论请求伤害为40%；报告记录真实HP差，致死损失封顶。
已验收：真实瞄准→锁定→起冲→扫掠碰撞实际扣2；剩余1.5生命时只记录1.5损失并归零失败。

SweepHitDamage = 1 HP
保留普通震击伤害，且普通震击不触发本次冲锋倒地。
理由：把两种攻击的代价区分开，避免本轮同时提高所有威胁。
已验收：普通震击仍扣1且不倒地；未命中冲锋不扣血、不倒地。

LastChargeDamageId = -1（开局初值；运行时存已处理的冲锋编号）
这是防重复结算的状态，不是平衡参数。每次开局重新设为-1；同一编号只应用一次，新的冲锋编号仍可造成伤害。
理由：一次真实碰撞可能有重复通知，不能让同次冲锋变成多次伤害。
已验收：同id不重复扣血，新id可再次造成伤害。开局重置已在最后保存的蓝图中明确执行。

CueHitWasCharge（布尔）与CueDamageSource（来源）
运行状态，用于把charge与普通攻击区分后选择对应伤害、记录实际损失，并只在冲锋时启动倒地。它们不代表玩家是否理解预警。

KnockdownNoticeUntil（提示结束时间）
命中时设为当前时间+1.2秒，用于给HUD足够的阅读时间。这是提示可见时长，不是控制时长；实际控制仍是0.8秒。
1.2秒来自当前蓝图实现，未作为可自由配置的独立设计参数暴露。若后续调整控制时间，应同步检查文案和提示节奏。

2. /Game/Step04/BP_GuardianPlayer
职责：执行受击动作、带碰撞的位移、输入/攻击拦截及存活恢复。

KnockdownSeconds = 0.8秒
从进入倒地状态起计算的总控制时间。期间禁用正常角色移动、忽略移动输入，并拦截TryAttack与DeliverAttack。
理由：不只是播放动作，而是让身体状态与能做的操作一致；输入被拒绝时有明确原因。
已验收：倒地期间普通移动无位移、不能发起或交付攻击；存活到期恢复步行、移动输入和F攻击。

KnockdownFallSeconds = 0.2秒
倒下阶段，同时根据冲锋方向执行击退。
KnockdownRiseSeconds = 0.25秒
存活恢复阶段，反向采样专用锁根副本，并将模型倾倒变换恢复到站姿。
中间停留 = 0.8 - 0.2 - 0.25 = 0.35秒
0.35是由三项时长计算的停留段，不是一个独立可编辑变量。调参时需保持总时长不小于倒下与恢复之和。
理由：把受击分成“冲击—短停—恢复”三段，便于观察节奏；这些秒数是当前原型设定，未获得真人舒适度结论。

KnockbackDistance = 100cm
沿该次冲锋方向，在倒下阶段尝试移动最多100cm。实现使用扫掠碰撞且关闭传送；遇到阻挡时实际距离可以小于100cm，不能把它写成每次必定击退1米。
理由：让空间后果可见，同时尊重场景碰撞。100cm为当前设计起点，不据此声称所有贴墙/角落组合都已覆盖。
证据范围：蓝图实现已核对bSweep=true、bTeleport=false；运行报告覆盖真实冲撞与控制恢复，没有独立穷举全部击退障碍布局。

KnockedDown（布尔）、KnockdownStartTime（时间）
用于避免重复进入倒地、计算阶段及统一阻止攻击。不是永久能力封锁。
KnockbackDirection、KnockbackOrigin（向量）
分别来自当次冲锋方向和进入倒地时的位置；属于运行数据，不应手工当作固定方向配置。
KnockdownAnimLength（约1.1秒）
来自原有MM_Death_Back_01及其专用副本的序列长度，用于姿势采样；不等于实际控制0.8秒，也不是另一个新增眩晕时长。
内部更新步长0.025秒用于姿势和位移采样，不是攻击冷却。

最终可见倒地：ApplyGuardianDownTransform
原MM_Death_Back_01带有根位移且身体主要后退屈膝，直接播放不能准确称为完整倒地。最终版本在专用副本中启用Force Root Lock并关闭Root Motion，再按倒地进度把Mesh的Roll从0变为-90°；同时将Mesh相对Z从-95cm补偿到-60cm，即最多抬高35cm，保证倾倒身体可见。
这组-90°与35cm是当前表现常量，不是角色胶囊的碰撞旋转/抬高；胶囊仍使用100cm带碰撞击退。不是布娃娃物理，也不是仅靠原动作倒放。
恢复时Roll归0、相对Z回-95cm，随后回到原动画蓝图。34项回归新增检查确认倒下姿态与高度、恢复旋转与偏移；最终原片的倒地、起身和复盘画面另有视觉核对。

攻击和死亡边界
TryAttack拒绝倒地中的新攻击请求；DeliverAttack阻止倒地前已开始前摇的延迟命中；FinishAttack的迟发清理不能提前解除移动封锁。
存活且战斗未结束，才会恢复正常动画/步行/输入。致死保持倒地禁用并进入失败；没有自动复活或额外闪避。
已验收：真实GameplayAbility前摇被冲锋打断后不能迟发命中；迟到攻击清理不解锁控制；死亡不恢复站立。

3. /Game/Step04/BP_GuardianHUD
职责：把伤害规则与倒地操作限制清楚显示给玩家，不参与扣血或恢复控制。
DrawChargeFeedback显示：
“冲撞伤害 2 · 倒地 0.8 秒期间无法移动 / 攻击”
最终文案说明该攻击的规则伤害，不声称所有命中都实际损失2。提示读取GameMode的结束时间；面板位置、底色和字号是表现常量，不是战斗平衡参数。
该数字文案目前为固定文本。若修改ChargeHitDamage或KnockdownSeconds，须同时更新HUD及视频说明，不能只改蓝图数值。
当前针对性运行报告ui_tested=false；这34项检查本身不包含HUD视觉验收或真人键鼠可读性测试。选定原片的可见姿态与复盘由单独画面核对确认，不混入断言计数。

三、Boss撞柱规则保持原基线
玩家被撞倒，与Boss撞柱进入眩晕易伤，必须分开理解。前者是玩家受罚，后者是利用场地创造的奖励。
运行记录中的实际参数快照：
BossMaxHealth = 24
AimSeconds = 1.2秒；LockSeconds = 0.8秒
ChargeSpeed = 1200cm/秒；ChargeLimit = 2000cm
StunSeconds = 3.2秒
VulnerabilityMultiplier = 1.5
initial_human_health = 5
当前仍有3根一次性柱，普通基础F伤害1。
本轮真实柱碰撞进入眩晕阶段并破坏已用柱；窗口内F造成1.5实际伤害。3.2秒来自本轮运行参数快照；这份针对性报告没有新增独立的眩晕到期计时断言，不能把参数读取说成重新测过所有时序。

四、动画来源与制作边界
原始资源：原工程已有Epic动画/Game/Characters/Mannequins/Anims/Death/MM_Death_Back_01。
本轮新增专用副本：/Game/Step04/A_GuardianKnockdown_InPlace。
专用副本从原资源复制，启用Force Root Lock、关闭Root Motion；共享原始动画未修改。保留骨骼反应，再由蓝图受控倾倒Mesh，恢复时反向采样并还原模型变换。
新增的是原资源衍生副本与原型表现逻辑，没有新增独立制作的专用起身动作，也不主张原创骨骼动画。此实现不是Ragdoll。
第一关选定原片已核对跌倒、仰倒、起身及复盘画面，身体反应清楚可见。画面核对支持这段表现可读，不能推出成品级动画、所有角度无问题或真人体验评价。

五、本轮第一关验证到底覆盖到哪里
第一关34项针对性运行检查通过；这是最终版本，不与早期重复检查累计。
记录来源automated；实际启动关卡，并有为覆盖边界而设置位置/调用状态入口的自动操作。不是外部玩家试玩，不是完全自然操作通关；报告明确ui_tested=false、editor_assets_saved=false。
覆盖：真实冲撞伤害、同id去重、倒地输入/攻击限制、存活恢复、真实前摇打断、未命中与普通震击区别、柱子破坏与1.5倍伤害、致死损失封顶及不恢复，以及最终Mesh倾倒和恢复姿态。
蓝图构建保存与运行检查分别记录；运行检查本身不保存编辑器资产。
这些运行检查不能推出外部玩家都能理解、0.8秒控制最舒服、碰撞所有组合无遗漏或已完成可分发游戏打包。原工程部署记录已确认：6份蓝图修改、1个动画副本新增，346个保护文件不变，地图与既有试玩记录保留。

六、第二关：正常输出的表现补充
已完成的原型修改涉及/Game/Step05/BP_FurnaceAllyA、BP_FurnaceAllyB与BP_FurnaceGameMode；构建通过，平衡参数未改。
AI原有合法攻击造成伤害后，PlayFurnaceStrike播放已有MM_Attack_01挥击；从动画0.14秒处开始，0.42秒后调用RestoreAIAnimation恢复原动画蓝图。恢复前检查角色仍存活。0.42秒是表现恢复时间，不是新的伤害间隔或额外攻击。
资源：/Game/Characters/Mannequins/Anims/Unarmed/Attack/MM_Attack_01.MM_Attack_01。动作沿用已有Epic人形资源，不主张新制作骨骼动作。
理由：AI已有数值输出应有对应身体反馈，使观众能看见任务间隙仍在战斗；表现只挂在已有伤害执行之后，不添加第二次扣血或动画通知伤害。
战斗平衡不变：Boss仍80HP，AI原0.5伤害/1.2秒攻击间隔保持；点名、炉工和地热规则不因录像而暗改。实际攻击会被移动、震击避让和点名任务打断，所以1.2秒不能被写成全程实际输出节奏。
第二关选定场次来源为staged，即编排演示。该局50.733336秒胜利，Boss实际HP损失为human槽位49、AI A 15、AI B 16，共80。
三轮点名约在4/20/36秒；第一轮9秒清理，第二轮不清理、26秒炉工完成，27–34秒产生8次热伤害，第三轮41秒再次清理。全队热损血4.8，每人1.6；本局实际误伤0。该场次12项记录核对通过。
该连续局展示“用持续输出换团队承伤”后仍获胜的一种可运行情境，不代表忽略机制普遍最优，也不能把第二轮不清理自动解释成玩家没理解或整场失败。50.7秒是这一条脚本编排局的战斗时间，不是玩家平均通关时间。各项数字来自这同一局，不混用其他录制。
录制修正包含导航就绪确认、Boss相对合法站位和正常F攻击入口；不注入伤害，不降低录像专用Boss生命。普通PIE诊断与最终连续录像分别保留来源，不混为外部试玩。

七、第三关与后续调参
第三关本轮没有战斗参数变更。采用同一场次原速连续原片，单局74.9秒胜利；2次平台预告，两次平台升起时均在台上，其中1次在预告时已位于安全区；可控角色成功Q 10次。该局可控角色核心实际伤害47、小怪实际伤害0，不能仅由此推断理解或最佳策略。
第三关保留同一原片从开始到本局结算的完整0–83.8秒，包含两轮毒潮；74.9秒是战斗时间，其余包含开场与结算展示。不插入其他场次的Q，不跳过击杀，也不把不同构筑拼成一场。独立完整原片见media/plague-full-run.mp4；2次升起时在台与Q 10次等统计仍只来自本局。

以后怎样继续调参
一次写清变更原因、预计行为和副作用，再对照同关卡、来源、版本和参数快照。视觉提示的颜色、时长、尺寸与文字也会影响理解，须记录，不能因伤害没变就认为条件相同。
保持行为、玩家中性原话和观察备注三者对应。首次与复试分开，人类与AI/脚本分开；未采集写未采集，取消/未完成不算成功。
当前结构化外部试玩0人。本人已有战斗/关卡经验，这是首次Unreal制作，由本人主导设计判断、AI辅助实现与检查；本轮自动验证和编排演示不能替代3–5位目标玩家的探索性试玩。
